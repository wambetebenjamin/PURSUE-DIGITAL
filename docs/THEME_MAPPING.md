# Theme mapping — Land of Empires → PURSUE (1 Samuel 30)

**What this document is.** The brief asked for a table of the original
decompiled variable names beside our themed ones. This is that table, and
then some: every name that came out of the decompiled source, every name we
invented to replace it, and — importantly — the list of things we deliberately
did **not** rename, because the name *is* the mechanic.

**Where the names came from.** Three sources, in descending order of authority:

1. `docs/reference/schema/sdk-schema.json` — generated by
   `tools/extract-java-schema.py` from the JADX dump: 113 Retrofit routes,
   229 `@SerializedName` payload classes, 675 error-code vocabularies.
2. `docs/reference/04-game-protocol.md` — the 39 `msg.gs.*` message names
   recovered from the Lua constant tables.
3. `docs/reference/05-game-logic.md` — the enums, constants and config tables
   the Lua reads by name.

## 2. The payload schema

The SDK's `Role` bean is the one game-shaped object in the Java layer. It
becomes our `Player`, field for field.

| `Role` field (decompiled) | Our field | Note |
| --- | --- | --- |
| `role_id` | `role_id` | unchanged — it is the identity |
| `name` | `name` | unchanged |
| `level` | `level` | unchanged |
| `server_name` | `server_name` | unchanged |
| `real_server_id` | `server_id` | unchanged |
| `login_time` | `last_login_time` | unchanged |
| `avatar_url` | `avatar_url` | unchanged (resolved from a constant) |
| `job` | `job` | unchanged — the captain's trade |
| `extra` | `extra` | unchanged |
| *(none)* | `session_token` | the token `exchange_token` hands out |
| *(none)* | `token_expires_at` | our addition; the SDK expires sessions too |
| *(none)* | `stars`, `renown`, `season`, `boon_active` | our progression fields |

**The envelope**, unchanged — it is the one contract worth keeping verbatim:

```json
{ "code": 0, "message": "ok", "data": { } }
```

**The error codes**, unchanged, taken from
`com.bytedance.ttgame.module.gameinfo.api.common.GameInfoErrorCode`:

| Code | Name | Meaning here |
| --- | --- | --- |
| `0` | — | success |
| `-130001` | `PARAM_ERROR` | a bad parameter, or a refusal ("not enough in the stores") |
| `-130002` | `TOKEN_INVALID` | the session is no good |
| `-130003` | `SERVER_LIST_EMPTY` | no shard is up |
| `-130004` | `OPEN_ID_ERROR` | the device could not be identified |
| `-130005` | `RISK_CONTROL` | refused by the anti-cheat |
| `-130006` | `SERVER_ERROR` | our fault |
| `-133001` | `NETWORK_ERROR` | the network is down |
| `-139999` | `UNKNOWN_ERROR` | anything else |

### Terrain → resource → tool

The reference's table is literal, and so is ours:

| Reference `TerrainEnum` | Reference `ResourceEnum` | Reference `ToolEnum` | Our yard | Our yields | Our tools |
| --- | --- | --- | --- | --- | --- |
| `Home` | `Coin` | `None` | `ziklag` | `bronze` | `none` — *The Storehouse* |

the whole ladder in every production building in the genre, and it is why

### Config tables

| Reference table | Ours | Where it lives |
| --- | --- | --- |
| `farmersworldtoolcfg` | `TOOLS` + `YARDS` | `game-backend/src/services/config.js` |
| `farmersworldactivitycfg` | `WORKS` (levels, caps, costs) | same |
| `itemcfg` | `RESOURCES` + the shop | same |
| `exchangecfg` | `EXCHANGE` | same |
| `seasoncfg` | `SEASON_OVERRIDES` | same |
| `serverinfocfg` | `SERVERS` | `game-backend/src/routes/auth.js` |
| `newbattlepassbasecfg` | `BOON` | `game-backend/src/services/config.js` |

**The important structural point:** in the reference these tables live in the
IL2CPP binary and are read at runtime. In ours they live on the **server**,
served at `GET /api/meta/config`. That is the reference's own model — the
season retunes the economy without a client update — and it is how a live
service is meant to work.

## 5. What we did **not** rename

These are the names that carry a mechanic, and changing them would change the
game:

- `C…` / `S…` / `SPush…` — the message-naming convention.
- `code` / `message` / `data` — the envelope.
- The SDK's error-code numbers.
- `Query` / `Output` — the split between *asking what is owed* and *taking it*.
- `gain` / `canGain` / `gainQuery` / `gainOutput` — the production vocabulary.
- `durability`, `stamina`, `populationCap`, `peopleCost` — in the config tables
  where the reference's names are kept in comments beside ours.

## 6. What was deliberately dropped

| Reference | Why |
| --- | --- |
| The ByteDance SDK spine (payments, compliance, IAP, share, ads) | it is the publisher's, not the game's; we keep the *shape* (login → token → shard list) and nothing else |
| The `farmersworld` farm mini-game | it is a side activity inside a city game; our camp does the same job with the same mechanics |
| `gloryfactory` crafting queue | kept in full, as the Works' timed slots — but in our own theme |
| The 113 Retrofit endpoints | they are not the game (see `docs/reference/03-api-inventory.md`) |
